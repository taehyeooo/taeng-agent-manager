# 다독CS 구현 계획

> 기준 문서의 버전이 바뀌면 이 계획을 다시 검토한다.

## 범위
- 포함: 기능명세서 v1의 요구사항 32개 전부, 개념 15개 콘텐츠
- 제외: 명세서 "범위 — 제외" 그대로 (실전 모드, 음성, 다중 사용자, 배포 등)

## 진행 방식
- 작업 1개 = PR 1개 = Orca 워커 1명, 1시간 안쪽. 배정은 `config/agents.json`대로 **Codex 우선(11/30까지)**, 검증은 반대 모델(Claude, reviewflow).
- 기반(레포·DB·콘텐츠 형식) → 콘텐츠 생성은 앱 개발과 **나란히**(서로 다른 파일) → 화면 기능 → 마무리 검증.
- 콘텐츠 초안은 11/30 전에 끝낸다(가정 4).
- 화면은 intaeng 디자인 4단계(구조 시안 3개 → 세부 시안 → 적용 → 고도화)를 먼저 하고, 시안 고르기는 사용자가 한다.

## 단계

### 0. 준비 (사람 손 — 승인)
1. [ ] JDK·PostgreSQL 설치, 서비스 레포 `dadok-cs` 생성(비공개) + intaeng 지식베이스 + 가드 훅 — 확인: `am doctor`, `java -version`, `psql --version`, 레포 CI 통과 (R-28)

### 1. 기반 (codex)
2. [ ] 레포 뼈대: Spring Boot + React(Vite) 한 레포, Gradle wrapper, 127.0.0.1 바인딩, CI(백엔드·프론트 테스트) — 확인: 서버가 0.0.0.0으로 열리지 않는 테스트, CI 통과 (R-28)
3. [ ] DB 스키마(Flyway): 표 16개와 제약(정답 1개·오답 원인 필수·캡처 조건 필수·제출 번호 유일) — 확인: 제약을 어기는 삽입이 실패하는 테스트(내장형 PostgreSQL)
4. [ ] 콘텐츠 형식(Markdown + YAML)·불러오기·검사 스크립트, 예시 개념 1개 — 확인: 검사 규칙마다 일부러 어긴 예제가 실패, CI에서 검사 실패 시 PR 막힘 (R-27)

### 2. 콘텐츠 (codex 생성 → claude 검증, 앱 개발과 병렬, 11/30 전)
5. [ ] 생성·검증 파이프라인 + 그림 관리 + 첫 3개 개념(③ 인덱스 ④ 실행 계획 ⑥ 커넥션 풀) — 확인: 3개 개념이 콘텐츠 검사 통과, 검증 기록 있음 (R-24)
6. [ ] 교차 검증 기록·노출 규칙(검증 안 된 것은 준비 중) + 사례 카드 사실 확인 절차 — 확인: 검증 기록 없는 콘텐츠가 화면에 안 나오는 테스트 (R-25)
7. [ ] 그림: 코드 그림(Mermaid·SVG)과 Trova 기록 캡처 + 측정 조건 캡션 — 확인: 캡션·대체 텍스트 누락 0 (R-26)
8. [ ] 나머지 12개 개념 콘텐츠(카드 6장·문제 5개 이상·체크리스트·용어) — 확인: 15개 모두 콘텐츠 검사 통과, 사례 카드 15장 사용자 사실 확인 완료

### 3. 디자인 (codex, intaeng design-flow — 사용자가 고름)
9. [ ] 구조 시안 3개(대시보드·개념 학습·튜터 화면) → 사용자 선택 → 세부 시안(글꼴·색·간격·다크 모드) → 사용자 선택 → 토큰 적용 — 확인: design-review 체크리스트 통과, 실제 빠르기로 한 번

### 4. 학습 화면 (codex)
10. [ ] 학습 지도: 개념 지도·상태 색 — 확인: 15개 개념·선행 화살표 렌더링 테스트, 실제 빠르기로 한 번 (R-3, R-4)
11. [ ] 개념 학습: 카드 6장 넘기기·출처 라벨·그림 확대 — 확인: 90장 E2E 넘기기, 라벨 표시 테스트 (R-6, R-8, R-9)
12. [ ] 용어 풀이 팝업과 갔다 돌아오기(최대 3단계) — 확인: GC → 힙 → 프로세스 → 돌아가기 E2E (R-5, R-7)
13. [ ] 다독 회차(7회차) 전환 — 확인: 회차 전환 단위 테스트 (R-10)

### 5. 문제와 복습 (codex)
14. [ ] 객관식·OX·원인 분석 풀이와 채점·해설, 중복 제출 방지 — 확인: 문제 화면 테스트, 같은 제출 번호 두 번 → 1건 (R-11, R-12, R-13)
15. [ ] 오답 원인 진단(보기의 원인 표시)과 약한 개념 우선 이동 — 확인: 6유형별 진단·이동 대상 테스트 (R-14, R-16)
16. [ ] 복습 일정(1·2·4·8·16·30일, 익숙함 판정, 밀린 복습, 하루 4시 기준)과 묶음 복습 — 확인: 일정 계산·경계 시각 단위 테스트 (R-15, R-17)
17. [ ] 홈 대시보드: 오늘 할 일과 하루 학습량 설정 — 확인: 설정에 따라 구성이 바뀌는 테스트, 실제 빠르기로 한 번 (R-1, R-2)

### 6. AI (codex, Spring AI 2 — 시작 전 공식 문서로 버전 확인)

19. [ ] AI 튜터: 설명하기·3번 되묻기·힌트 — 확인: 가짜 CLI 대화 테스트, 실제 CLI로 표본 20개 중 모범답안 직접 제공 0 (R-18, R-19)
20. [ ] 설명 평가: 체크리스트 비교·점수·통과 판정·평가 대기·형식 오류 처리 — 확인: 정답·오답 설명 표본 평가 테스트 (R-20)

### 7. 기록과 기반 (codex)
