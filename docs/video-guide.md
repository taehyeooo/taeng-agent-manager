# 영상 가이드 — 릴스·쇼츠·홍보 영상·모션 그래픽

매니저는 영상 작업을 계획하기 전에 이 문서를 처음부터 읽는다. 사용자 지시(2026-11-23)에 따라 **레퍼런스를 먼저 추천하고, 사용자가 고른 뒤 장면을 구성한다.**

## 1. 진행 순서

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 1. 요청 확인 | 매니저 | 시청자가 영상을 보고 무엇을 알거나 하길 원하는지, 영상 길이, 올릴 곳(인스타그램 릴스·유튜브 쇼츠·스레드 등)을 확인한다. 요청에서 빠진 항목만 묻는다. |
| 2. 레퍼런스 추천·선택 | 매니저 → 사용자 | 아래 표의 Prompt Motion부터 살펴보고 요청에 맞는 작품 3개 안팎을 고른다. 작품별 **직접 링크, 글자 크기, 색, 컷이 바뀌는 속도, 화면 녹화가 차지하는 비중**을 나란히 보여 주고 사용자가 고르게 한다. 사용자가 링크를 주면 해당 영상을 직접 재생해 장면을 확인한다. 로그인 화면에서는 비밀번호를 입력하지 않는다. 재생할 수 없으면 그 사실을 알리고 공개 링크나 영상 파일을 요청한다. |
| 3. 구조 정하기 | 매니저 | 선택한 작품에서 참고할 점을 짚고 구간별 시간과 메시지를 정한다. 사용자 제공 예시(2026-11-23)는 Hook(눈길을 끄는 첫 장면) → Problem(불편) → Solution(해결 방법) → Demo(실제 앱 시연) → CTA(다음 행동 안내)다. |
| 4. 제작 위임 | Codex 워커 | 매니저가 건넨 장면 구성과 아래 제작 규칙에 따라 `trova-marketing` 레포의 `video/` 도구를 재사용해 영상과 장면별 프레임 미리보기를 만든다. |
| 5. 검수·전달 | 매니저 | 최종 영상에서 뽑은 장면별 프레임을 순서대로 보며 큰 글자가 읽히는지, 실제 앱 화면과 문구가 맞는지 확인한다. 영상을 재생해 컷 속도와 글자를 읽을 시간을 점검한다. 사용자가 슬랙 발송을 요청한 경우에만 확인한 결과물을 한 번 보낸다. |
| 6. 결과 보고 | 매니저 | 최종 영상 및 프레임 미리보기와 함께, 4장 표에 구간별 큰 글자와 화면 종류를 기록한다. |

## 2. 용도별 레퍼런스 사이트

| 사이트 | 무엇을 볼 때 | 메모 |
|---|---|---|
| [Prompt Motion](https://prompt-motion.com/) | **사용자가 지정한 1순위.** Claude로 만든 모션 그래픽 영상과 작품별 프롬프트·스킬을 함께 살펴볼 때 | 앱 시연은 Product UI·Phone, 움직이는 글자는 Kinetic type, 설명 장면은 Charts·Diagrams·Characters 필터부터 본다. 프롬프트는 원 작성자의 저작권과 이용 조건을 확인해 복사·변형하고 출처 링크를 유지한다. |
| [Meta 광고 라이브러리](https://www.facebook.com/ads/library) | 국내 앱이 실제 집행 중인 인스타그램·페이스북 광고(릴스 포함)의 흐름을 볼 때 | 국가를 대한민국으로 두고 첫 장면부터 앱 시연까지의 순서를 본다. |
| [TikTok Creative Center (Top Ads)](https://ads.tiktok.com/business/creativecenter) | 성과가 좋은 숏폼 광고의 도입부와 컷 속도를 비교할 때 | Top Ads에서 업종·지역을 좁힌다. |
| [Mobbin](https://mobbin.com) | 실제 앱 화면과 흐름으로 데모 장면을 구성할 때 | 일부 흐름은 영상으로 볼 수 있다. 무료 공개 범위에서 살펴본다. |
| [Screensdesign](https://screensdesign.com) | 앱 화면·온보딩 녹화에서 조작 순서를 볼 때 | 어떤 조작부터 결과 화면까지 보여 주는지 본다. |
| [Dribbble (Motion)](https://dribbble.com/search/motion) | 짧은 UI 모션이나 전환 아이디어를 찾을 때 | 화면 요소가 등장하고 사라지는 타이밍을 본다. |
| [Jitter](https://jitter.video/templates) | 제품 UI 모션 템플릿의 구성을 볼 때 | 글자와 제품 화면이 번갈아 등장하는 순서를 참고한다. |
| [Rotato](https://rotato.app) | 휴대폰 목업이 기울거나 회전하는 연출을 볼 때 | 공개 예시만 참고한다. 유료 앱은 구매하지 않는다. |

레퍼런스에서는 **구성·리듬·타이포그래피 방식만** 가져온다. 문구·로고·캐릭터·화면·색 조합을 그대로 쓰지 않는다. 유료 가입이나 구매에는 사용자 승인(`paid_service`)이 필요하므로 레퍼런스를 찾을 때는 무료 공개 자료를 사용한다.

## 3. 작업자 지시문에 넣을 제작 규칙

- 선택한 작품의 링크, 참고할 연출, 게시할 곳과 길이, 구간별 메시지를 적는다. 결과물로 최종 영상과 각 장면의 대표 프레임을 요청한다.
- 앱 장면에는 **실제 앱에서 녹화하거나 캡처한 화면만** 쓴다. 그린 앱 화면은 금지한다. 실제 앱 안에 표시할 데이터만 데모용으로 준비한다.
- **Trova 홍보 영상**에는 가격·수치·실제 사용자 정보·과장 표현·지어낸 경험담을 넣지 않는다. 일정은 “초안”으로 표시하고 “AI가 장소를 잘못 찾을 수 있어요”를 넣는다. 끝 줄은 “링크는 프로필에”로 쓴다.

## 4. 구간별 보고 형식

최종본을 기준으로 장면마다 한 줄씩 채운다. 큰 글자는 화면에 나온 문구 그대로 쓰고, 없으면 ‘없음’으로 적는다. 다음은 Trova 영상의 작성 예시다.

| 구간 | 화면에 나온 큰 글자 | 화면 종류와 내용 |
|---|---|---|
| 0–3초 · 도입 | 여행 계획, 어디서 시작할까? | 글자 연출 · 질문을 한 줄씩 표시 |
| 3–8초 · 시연 | 여행 일정 초안 | 실제 앱 녹화 · 데모 여행의 일정 화면 열기 |
| 8–12초 · 마무리 | AI가 장소를 잘못 찾을 수 있어요<br>링크는 프로필에 | 글자 연출 · 안내 문구와 끝 줄 표시 |
