언제 쓰나: 디자인 QA 때 웹페이지·앱 모두, 45개 패턴 점검보다 먼저. 작업자 지시문에 내용을 옮겨 적는다.

현재 프로젝트의 주요 화면을 살펴보고, 사용자가 내용을 읽거나 다음 행동을 찾기 어렵게 만드는 디자인을 개선해줘.

먼저 프로젝트 구조를 확인하고, 가능하면 직접 실행해서 첫 화면과 핵심 기능 화면을 봐줘. 이 서비스에서 사용자가 가장 먼저 봐야 할 정보와 자주 누르는 버튼이 무엇인지 파악한 뒤 수정해줘.

점검할 때는 간격 → 색 → 아이콘 → 문구 → 글자 크기와 굵기 → 배치 → 테두리와 그림자 → 이미지 → 움직임 순서로 살펴봐줘. 특히 아래 상황을 확인해줘.

- 버튼과 카드가 모두 강한 색이나 그림자로 강조돼 정작 중요한 행동을 찾기 어려운 곳
- 관련된 정보끼리 간격이 너무 넓거나, 서로 다른 항목이 너무 붙어서 한 덩어리로 보이는 곳
- 같은 기능인데 화면마다 아이콘, 버튼 이름, 위치가 달라 헷갈리는 곳
- 제목을 그대로 반복하는 설명, 과한 감탄 표현, 기능을 알아보기 어려운 이모지
- 애니메이션 때문에 내용을 읽거나 다음 동작을 하는 데 방해가 되는 곳

그라데이션이나 이모지는 이 서비스의 브랜드나 기능에 어울리면 유지해줘. 개선할 이유가 분명한 부분부터 기존 공통 컴포넌트와 디자인 스타일을 활용해 직접 수정해줘.

마지막에는 수정한 화면을 다시 확인하고, '어느 화면에서 무엇이 불편했고 어떻게 바꿨는지'를 짧게 정리해줘. 실행 화면을 확인하지 못한 경우에는 코드로 판단한 부분을 구분해서 알려줘.
